# Gimbal_um

> v26.1.1.0重构了仓库
>
> v26.1.2.0重大变更：修改了**通讯协议**，修改了`0x84`字节的语义

一套基于 `STM32F405RGT6` 的双轴云台固件工程，面向 `GM6020` 偏航 / 俯仰双电机控制，集成 `CAN2`、`BMI088` 姿态解算、`USB CDC` 上位机通信和 `FreeRTOS` 实时任务调度。

## 工程概况

工程采用分层结构组织：

- `Core/`：STM32CubeMX 生成的启动、时钟、外设初始化和 RTOS 入口。
- `User/Bsp/`：底层外设封装，包括 `CAN`、`IMU` 和 `USB`。
- `User/Device/`：设备抽象层，目前以 `GM6020` 电机对象为核心。
- `User/Module/`：控制与算法模块，包括 `PID`、电机管理、姿态融合。
- `User/Task/`：FreeRTOS 任务与控制状态机。

系统的控制链路为：

`USB 上位机指令 -> 协议解包 -> 消息队列 -> 控制任务 -> 姿态融合 / 模式切换 -> 电机控制 -> CAN 输出`

## 面向上层的使用方式

这份文档主要给视觉、上位机或其他调用者使用。上层只需要按协议发送控制帧，并解析状态反馈即可，不需要关心内部控制实现。

### 初始化顺序

建议上位机连接后先发送：

1. `0x82` 开启数据传输
2. 再根据业务需要发送 `0x83`、`0x84`、`0x87`、`0x88`

如果没有先发送 `0x82`，下位机默认不会主动发送状态反馈。

### 调用建议

- 上位机先打开反馈，再决定进入搜索、自瞄或锁定流程。
- 自瞄场景下建议按固定频率持续发送 `0x84`，因为它是增量修正接口。
- 如果需要临时停止控制，优先发送 `0x87` 进入锁定保护；恢复时再发送 `0x88`。
- 解析状态时主要关注 `0x03` 里的 `mode` 和角度字段即可。
- 当前代码不会因为“上电后一直没有串口消息”而自动进入锁定保护。

### 上电与连接顺序

如果你的通信线会带供电，推荐按下面顺序操作：

1. 先给云台主电上电，让控制板、电机和 IMU 完成启动。
2. 再接入 USB / 串口通信线，建立上位机连接。
3. 上位机发送 `0x82` 打开状态反馈。
4. 根据需要切换到搜索、自瞄或锁定流程。

这样做的好处是，云台先完成硬件初始化和姿态稳定，再进入通信控制，现场调试时更安全，也更不容易出现“通信线先供电、主电未就绪”的状态差异。

## 对外通信协议

### 帧格式

USB 数据帧采用固定格式：

`SOF(0xAA 0x55) + LEN + CMD + DATA + CRC16(MODBUS) + EOF(0x5A 0xA5)`

- `SOF`：帧头，固定为 `0xAA 0x55`
- `LEN`：`DATA` 的字节长度
- `CMD`：命令字
- `DATA`：负载数据
- `CRC16`：对帧头、长度、命令字和数据做 `CRC16/MODBUS`
- `EOF`：帧尾，固定为 `0x5A 0xA5`

### 控制命令

#### `0x82` 开启数据传输

- `DATA`：空
- 作用：允许下位机开始发送状态反馈

#### `0x83` 进入搜索模式

- `DATA`：`uint32_t time_stamp`
- 作用：切换到搜索模式
- 说明：时间戳用于上层同步，不影响控制含义

#### `0x84` 自瞄增量输入

- `DATA`：
  - `int16_t yaw_x100`
  - `int16_t pitch_x100`
  - `uint32_t time_stamp`
  - `int16_t yaw_rate_dps`
- 作用：以上位机估计的绝对目标和 yaw 角速度共同描述当前自瞄目标
- 说明：
  - `yaw_x100` 和 `pitch_x100` 均以 `0.01deg` 为单位
  - `yaw_rate_dps` 以 `deg/s` 为单位，用于延迟补偿和 spin 判定
  - yaw、pitch 的方向定义需要与上位机约定一致

#### `0x87` 进入锁定保护

- `DATA`：空
- 作用：进入锁定保护状态，停止常规控制输出

#### `0x88` 退出锁定保护

- `DATA`：空
- 作用：退出锁定保护，并切回稳定模式

### 状态反馈

#### `0x03` 云台状态反馈

该报文用于告诉上位机当前云台状态。

- `DATA`：
  - `int16_t yaw_target_x100`
  - `int16_t pitch_target_x100`
  - `int16_t roll_target_x100`
  - `uint32_t time_stamp`
  - `uint8_t mode`
  - `uint8_t reserved`
- `mode` 含义：
  - `0`：稳定模式
  - `1`：搜索模式
  - `2`：自瞄模式
  - `3`：锁定保护
  - `4`：失能保护保留值，当前代码路径下通常不会主动进入

#### `0x08` 锁定反馈

该报文用于确认锁定状态或锁定原因。

- `DATA`：
  - `uint32_t time_stamp`
  - `uint8_t reason`
- `reason` 当前常用值：
  - `1`：手动锁定

## 丢失目标后的处理流程

这部分是给上层调用者最需要关注的内容。

### 自瞄丢目标

当上位机进入 `AUTO_AIM` 后，如果一段时间内没有继续发送 `0x84` 增量修正命令，系统会认为当前目标已丢失或视觉链路中断，并自动进入搜索流程。

### 处理顺序

1. 自瞄断流后，系统先回到局部搜索。
2. 局部搜索持续一段时间后，扩大到全局搜索。
3. 如果搜索阶段长时间没有新的控制消息，系统会回到稳定模式。
4. 当前代码不会因为“长时间没有串口消息”而自动进入锁定保护。

### 对上位机的建议

- 自瞄时请持续发送 `0x84`，不要只发一次。
- 如果视觉重新识别到目标，继续发送新的 `0x84` 即可，系统会在当前状态基础上修正目标。
- 如果想明确结束当前搜索或自瞄流程，可以发送 `0x83` 切回搜索，只发一次，或者发送 `0x87` 进入锁定保护。

### 当前锁定触发条件

按当前代码，锁定保护主要由下面两类情况触发：

- 上位机显式发送 `0x87`
- IMU 不在线时，控制任务会进入锁定输出路径

仅仅因为“没有新的串口消息”并不会直接触发锁定保护。

## 时序说明

- 控制主循环按 `1ms` 周期执行，适合固定频率更新目标和读取反馈。
- 状态反馈默认按约 `10ms` 周期发送，上位机不需要高频轮询。
- `0x84` 自瞄增量输入建议持续、稳定地发送，避免长时间断流后目标更新不连续。
- 搜索模式由下位机内部自动推进轨迹，上位机只需要切换模式并接收反馈即可。
- 锁定保护属于更高优先级状态，一旦进入后会压制常规控制输出，直到收到 `0x88` 解锁命令。
- 搜索阶段在当前代码里会因超时回到稳定模式，而不是因无串口消息自动锁定。

## 主要功能

- 双轴云台闭环控制，支持 yaw / pitch 两个自由度。
- 基于 `BMI088 + MahonyAHRS` 的姿态融合，输出世界坐标系下的 `yaw / pitch / roll`。
- 基于 `GM6020` 反馈的双环控制，外环位置、内环速度。
- `USB CDC` 上位机通信，支持控制指令、状态反馈和锁定反馈。
- 软件限位与保护逻辑，防止电机动作越界。
- 基于 `FreeRTOS` 的实时任务调度，控制主循环按 1ms 周期运行。

## 工作模式

工程定义了以下业务模式：

- `STABLE`：稳定模式，云台保持对地姿态。
- `SEARCH`：搜索模式，云台按预设轨迹扫描目标区域。
- `AUTO_AIM`：自瞄模式，根据上位机发送的增量误差修正目标角度。
- `LOCK`：锁定保护，停止输出并保持保护状态。
- `DISABLE`：协议中保留的状态值，当前代码里通常不主动进入。
